## 1. Mini-GPT 的数据流

Mini-GPT 去掉 Encoder 和 cross-attention，只保留带 causal mask 的 decoder self-attention：

```text
idx (B, T)
  -> token embedding + position embedding
  -> N 个 GPTBlock
  -> LayerNorm
  -> lm_head
  -> logits (B, T, V)
```

训练目标是让每个位置预测下一个字符。标签是输入右移一位，因此长度为 128 的样本一次提供 128 个分类任务。计算交叉熵时，将 `logits.reshape(-1, V)` 与 `targets.reshape(-1)` 展平，把每个位置视为一个独立的分类题。

## 2. 权重共享

`nn.Embedding(vocab, d)` 和 `nn.Linear(d, vocab)` 的权重形状都是 `(vocab, d)`：Embedding 按行查表，输出层按行与隐藏状态做点积。因此可以让输入和输出使用同一组词表表示：

```python
self.head.weight = self.tok.weight
```

仅仅创建两个层并不会共享参数。`bias=False` 让输出层与 Embedding 的矩阵形式更对称，通常也足够表达字符分类的主要信息。

共享权重后，初始化方式会直接影响初始 logits 的幅度。若 Embedding 使用默认的较大尺度再直接作为输出层，初始 loss 可能异常高；可以显式使用类似下面的初始化：

```python
nn.init.normal_(self.tok.weight, mean=0.0, std=0.02)
```

## 3. 自回归生成的关键细节

`generate` 每轮只生成一个字符，`max_new` 决定新增字符的数量。

- `idx[:, -self.block:]` 只保留最近的 `block` 个字符，避免超过位置编码表的长度。
- `logits[:, -1]` 只取最后一个位置的预测；前面位置对应已知上下文，不需要重复采样。
- 除以 `temperature` 会统一缩放候选字符的分数。温度小于 1 更保守，大于 1 更随机。
- `topk` 返回候选值和下标。用第 k 大的值作为阈值，并把其余 logits 设为 `-inf`：

```python
v, ix = torch.topk(logits, min(top_k, logits.size(-1)))
logits[logits < v[:, [-1]]] = -float("inf")
```

`v[:, [-1]]` 保持 `(B, 1)`，可以正确广播；写成 `v[:, -1]` 会降成 `(B,)`，在某些形状下无法按预期对齐。随后用 softmax 得到概率，再用 `multinomial` 随机抽样，而不是直接取 `argmax`。新字符通过 `torch.cat([...], dim=1)` 接到序列末尾。

## 4. 训练循环与参数更新

一个训练 step 的顺序是：

```python
optimizer.zero_grad()
logits, loss = model(x, y)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()
```

梯度默认累加，所以每步都要先清零。梯度裁剪必须发生在 `backward()` 之后、`step()` 之前；它限制整体梯度范数，主要用于避免梯度爆炸。AdamW 的 `weight_decay` 是解耦的权重衰减，每步按比例缩小参数，常见做法是只对矩阵参数衰减，不对 bias 和 LayerNorm 参数衰减。

调用模型应使用 `self(x)`，而不是手动写 `self.forward(x)`，因为 `__call__` 还负责钩子等 PyTorch 机制。`gpt(*get_batch("val"))` 等价于先取出 `(x, y)` 再调用 `gpt(x, y)`。

## 5. 需要反复确认的形状操作

- `reshape(-1)` 把张量展平成一维，`-1` 由 PyTorch 自动推算长度。
- `x[:, -1]` 会去掉最后一维；`x[:, [-1]]` 和 `x[:, -1:]` 保留长度为 1 的维度。
- `cat` 沿已有维度拼接；`stack` 会新建一个维度。
- 读取模型代码时，逐步标记 `(B,T,V)`、`(B,V)` 和 `(B,1)`，许多 bug 都能在形状对齐时被发现。

## 6. 遇到的问题与解决

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 生成文本很奇怪、像是没有学到 | 之前在 CPU 上训练，速度慢；训练步数少，字符级模型也容易拼错词 | 切换 Colab GPU，重启后重新运行所有单元，并增加训练步数 |
| 不确定输出是否正常 | 缺少客观判断标准 | 看验证集 loss：约 4.17 接近随机水平，2.0–2.5 表示开始学会拼写，约 1.5–1.9 可作为小模型的参考区间 |
| 权重共享后初始 loss 偏高 | 共享后的输出 logits 幅度过大 | 创建模型后对 token/position 参数使用较小标准差初始化 |
| MHA 调用参数对不上 | `forward` 曾有 `(x_q,x_kv,mask)` 与 `(q,k,v,mask)` 两种签名 | 先确认定义，再按签名传参；复杂调用用关键字参数 |

这些 loss 区间是调试参考，不替代本次实际运行结果。当前记录没有虚构训练曲线或生成样例；下一步会在 GPU 上重新跑通并保存日志。

## 7. 开训前的检查清单

1. 打印 `device`，并确认 `next(model.parameters()).device` 与输入一致。
2. 检查 `self.head.weight is self.tok.weight` 或参数对象是否确实共享。
3. 确认初始 loss 是否大致接近 `ln(V)`，再开始长时间训练。
4. 用 `model.eval()` 做因果性测试，修改未来字符后检查过去位置输出不变。
5. 先过拟合一个 batch：如果连一个 batch 都记不住，优先查实现；能记住后再调整数据和训练配置。
6. 同时观察 loss 曲线和生成文本，loss 是更稳定的客观指标。
